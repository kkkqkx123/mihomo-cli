# 部署脚本方案

`deploy` 目录自包含构建、配置初始化与系统服务，仓库根不再保留可被误拾取的示例配置。

## 目录划分

* 构建脚本归拢到 `deploy`，产物仍输出到仓库 `build` 目录。
* 配置模板归拢到 `deploy`，包括 TOML 示例与 Mihomo 内核示例，删除仓库根示例与演示目录。
* 系统服务模板归拢到 `deploy`，安装时按实际路径渲染，不在仓库中写死绝对路径。

## 配置初始化

* CLI 连接配置由二进制自带的初始化命令生成，保证权限与校验一致。
* TOML 与内核配置由模板复制生成，已存在时默认跳过，显式强制才覆盖。
* 目标路径固定为各平台用户目录与内核标准路径，不探测当前目录。

## 系统服务

* 服务安装与开机自启分为两个独立选项，自启要求已安装服务。
* 默认安装用户级服务，系统级服务需显式指定并具备管理员权限。
* 服务单元复用现有守护进程逻辑，安装脚本仅负责渲染路径与重载服务管理器。

## 安装编排

* 构建、服务、自启均为可选项，默认缺二进制时构建，其余默认关闭。
* 重复执行安全，配置不覆盖，服务单元可重渲染。
* 非 Linux 平台不自动写服务，只给出对应平台的手动指引。
