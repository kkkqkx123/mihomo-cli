# CLI 配置整改方案

目标是让一份 YAML 配置有单一可信的加载入口，优先级清晰为默认值低于配置文件，配置文件低于环境变量，环境变量低于命令行标志。所有业务命令使用同一份经过校验的运行时配置，修复命令不受非法配置阻塞。

方案描述以自然语言为主，不展开完整代码实现。

## 阶段划分

### 第一阶段：加载优先级与默认值单源

* 将 Viper 默认值改为取自默认配置函数，避免三处硬编码漂移。
* 补充环境变量键分隔符映射，使嵌套配置可被环境变量覆盖。
* 移除重复的启动初始化，只在命令执行前初始化一次。
* 命令行覆盖只在标志被显式使用时生效，不再用非零判断覆盖文件值。
* 全局 `--config` 路径对所有命令生效，作为显式配置文件来源。

### 第二阶段：读写对称与持久化加固

* 加载与保存统一使用结构化编解码，不再混用两个 Viper 实例。
* 保存覆盖全部字段，加载后回写不再丢失数据。
* 保存前做完整校验，非法配置拒绝落盘并给出明确原因。
* 去掉加载保存过程中的直接打印副作用，由命令层统一输出。
* 配置目录按需创建，配置文件采用仅属主可读写权限，原子写入避免半截文件。

### 第三阶段：子命令一致性

* `config init` 尊重全局 `--config` 路径，存在时需显式强制覆盖。
* `config show` 改为展示 CLI YAML 的运行时配置与生效路径，密钥脱敏展示，支持表格与 JSON 两种输出。
* `config set` 直接编辑配置文件而非运行时，避免把临时命令行覆盖持久化。
* `config set` 支持全部可维护键，包括代理测速与输出相关键，键名同时兼容短别名。
* 缺文件时从默认配置起步，文件存在但非法时直接报错，引导用户用初始化命令显式修复，不再静默丢弃原有内容。

### 第四阶段：启动校验与排错友好

* 非配置类命令在启动时做一次结构化校验，非法地址、端口、超时等提前失败并提示修复命令。
* 配置类命令豁免启动校验，保证坏配置仍可查看与修复。
* 统一缺文件语义：缺文件视为使用默认值加显式初始化建议，非法文件视为错误。
* 保留 TOML 用于被托管内核配置，与 CLI YAML 职责边界保持不变，仅修正文档与提示避免混淆。

## 驗收思路

* 默认启动无配置文件时使用内置默认值并正常工作。
* 指定 `--config` 后查看与设置作用于同一路径。
* 未显式传超时标志时文件值保留，显式传标志时覆盖生效。
* 保存后重新加载字段无丢失，非法值无法落盘。
* 非法配置文件下普通命令给出明确错误，配置命令仍可执行修复。
* 密钥在展示时脱敏，落盘文件仅属主可读写。

## 非目标

* 不引入新的配置框架或替换 Viper 与 TOML 库。
* 不合并 YAML 与 TOML 为单一文件。
* 不调整输出包与配置包之间的类型归属，只做最小必要的解耦说明。
* 不批量改造所有业务命令的客户端构造方式，仍通过 Viper 提供运行时值，但由启动校验保障有效性。
